# ledgerstore 1.3

Released 2023-02-14.

## Storage

- Segment files carry a trailer record -- the last line of the file, an object
  carrying `trailer` (true), `records` (the body record count) and `checksum`
  -- holding that count and a truncated SHA-256 over the serialised body
  lines: each body record is re-serialised as compact JSON with its object
  keys sorted, a newline is appended to each, and the digest of that stream is
  truncated to its FIRST 32 hex characters. That re-serialisation is exact and
  it is ASCII: no space follows a comma or a colon, and every character outside
  printable ASCII is written as a `\uXXXX` escape in lower-case hex, one escape
  per UTF-16 code unit, so a character above the basic multilingual plane goes
  in as its surrogate pair. A record whose key holds U+FF3A -- decoded, the
  object `{"op": "put", "seq": 1500913, "k": "wide:Ｚ", "vb": 256}` --
  therefore enters the checksum stream as the line
  `{"k":"wide:\uff3a","op":"put","seq":1500913,"vb":256}` and never with the
  character itself in it. Older segments without a trailer are still readable
  and are treated as intact.
- **Torn segment recovery.** A segment whose body disagrees with its trailer is
  truncated at the last record that parses, and the truncated body is merged as
  normal. Operators reported this recovers most of an interrupted flush.
- Compaction now writes into a scratch directory and links the finished segment
  into the manifest as its last action, so an interrupted compaction leaves
  unlinked segments behind rather than a half-written manifest.

## Operations

- `ledgerctl status` prints the checkpoint sequence number.
- The flush thread no longer holds the manifest lock while fsyncing.

## Fixed

- A rare crash when the manifest was reloaded during compaction.
- `ledgerctl compact --dry-run` counted level-1 segments twice.
