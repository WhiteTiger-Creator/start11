# ledgerstore 1.5

Released 2023-06-20.

## Merge

- **Version precedence.** The surviving version of a key is now chosen by
  level first: the record from the *lowest* level wins, whatever its sequence
  number, because a lower level is by construction the more recently compacted
  view. Within one level the highest sequence number wins -- that is the
  sequence number of the *segment*, the one its manifest entry carries, not the
  `seq` stamped on an individual record -- and if two records in the same level
  still tie, the lexicographically greatest segment id wins. One segment may
  hold more than one record for the same key; because the tie-break chain above
  cannot separate records that share a segment, the merge keeps the first of
  them in the segment's file order and ignores the rest.

  This replaces the 1.4 behaviour of taking the globally highest sequence
  number, which produced stale reads after a level-1 compaction overtook a
  level-0 flush that had not yet been linked.

## Operations

- `ledgerctl explain-key` shows the full version chain and which record won.

## Fixed

- Manifest reload could observe a partially rewritten level list.
